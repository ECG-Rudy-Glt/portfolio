## Docker Compose

A single `docker compose up` is enough, after a script that generates the secrets. The stack separates three networks: `data` (internal, with no Internet access) for the database and backups, `edge` (outbound allowed) for the application, which must reach the AI APIs, Garmin and wger, and `llm` for an optional local model. Secrets are files mounted in `/run/secrets`. Optional profiles add an HTTPS proxy (Caddy), daily backups or Ollama. A one-off service imports the exercise library on first start and then steps aside.

## Exposure: a guide rather than a single recommendation

Because users do not all have the same network, the documentation compares the options: **VPN** (Tailscale, WireGuard: recommended, nobody else can even reach the login page), **Cloudflare Tunnel** with an access layer in front, **ngrok** for a demo, or a **reverse proxy with port forwarding**. For each: what is exposed, the settings to enable (allowed hosts, secure cookies, trusted proxy) and a checklist before opening. It also reminds that HTTPS is mandatory to install the PWA and receive notifications.

## Installing the app on a phone

The guide describes step by step how to add it to the home screen on **iPhone** (Safari, notifications from iOS 16.4 for an installed application), on **Samsung** (Samsung Internet, with the battery setting so that reminders arrive) and on Chrome Android, as well as the trust to grant to a private certificate authority when you have no public certificate.

## In production at home

On my homelab, the same application runs on k3s, deployed with GitOps: Flux follows the repository and applies the image tag it contains. CI knows how to build the image and update the tag; pushing the image to my registry is still done by hand, and automating it is an open point. Daily logical backups of the database add to those of the virtual machine. The public version and my production version are two repositories: one additionally contains my private manifests, the other is generated by a script that excludes them and fails if anything private slips in.

## CI and images

On GitHub, each PR runs lint, tests (with PostgreSQL), dependency audit, an image build with stack startup and header checks, and secret scanning. Each `vX.Y.Z` tag publishes a multi-architecture image (amd64 and arm64) to the GitHub registry.
