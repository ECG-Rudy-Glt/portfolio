A **platform engineer** builds an internal platform managed as a product, for developers. A
**harness engineer** builds the environment around a language model, so that an agent can carry out
multi-step work reliably. My view: a harness is a platform whose user is a model.

This path lines the two up. The **Platform** (P1 to P6) and **Harness** (H1 to H6) tracks run in
parallel for six months, then two **convergence** modules bring them together: a platform that runs
agents, and an incident triage agent evaluated on my real post-mortems.

It is a plan, not a report: the labs are still to be done, and each one will leave a verifiable
trace. The story behind it is in the (French) blog article
[Platform engineer et harness engineer](/blog/parcours-platform-harness/), with an explorable
version of the path.

The pages below detail each module: goals, concepts, sources, homelab lab and validation checklist.
